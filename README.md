# gomoseko

Roblox-проект на [Rojo](https://rojo.space): подземный хаб (боевая яма с манекенами, храм «Комната порталов»,
торговые палатки) и интерфейс в стиле World of Warcraft (фреймы игрока и цели с HP/маной, 4 слота для колец,
меню «Инвентарь» и «Магазин»). Первое кольцо — «Дуговая молния» (Arc Lightning).

Карта не хранится в репозитории как набор деталей: она **генерируется кодом** при старте сервера
(`src/server/BuildHub.server.luau`) в `Workspace.MainHub`. Весь проект остаётся текстовым и читаемым в диффах.

## Структура

```
default.project.json         # маппинг папок в DataModel
rokit.toml                   # версии инструментов (rojo, stylua)
src/
  shared/
    Config.luau              # константы хаба: размеры, цвета, порталы, настройки манекенов
    Types.luau               # общие типы (скилл, кольцо, состояние инвентаря, звено молнии)
    Remotes.luau             # ремоуты: сервер создаёт (init), клиент получает (get)
    Configs/
      CombatConfig.luau      # тег Enemy, мана, допуски, радиус Tab-таргета
      Skills/ArcLightningConfig.luau  # урон, радиусы, задержка, кулдаун, мана, цвета/звук молнии
      Rings/RingsConfig.luau # определения колец и стартовые предметы
    Combat/ChainSearch.luau  # чистый поиск следующей цели цепи (без Roblox API)
    Combat/Progression.luau  # уровни и опыт (чистая математика)
    Combat/CooldownMath.luau # геометрия «часиков» кулдауна (чистая математика)
  server/
    BuildHub.server.luau     # генератор карты, свет, SpawnLocation, манекены (тег Enemy)
    Dummies.server.luau      # урон по манекенам (касание Tool), HP-бар, респавн через 4 с
    Main.server.luau         # бутстрап: создаёт ремоуты и запускает сервисы
    Services/
      PlayerStatsService.luau  # мана и опыт игрока (атрибуты Mana/MaxMana, Level/XP/XPToNext)
      InventoryService.luau    # инвентарь колец и надетые слоты (сервер — источник правды)
      CombatService.luau       # каст (с CastTime), валидация, цепочка прыжков, урон, опыт, визуал
  client/
    Main.client.luau         # точка входа: UI, контроллеры, горячие клавиши (1-4, Q, Tab, I, B, Esc)
    Controllers/             # InventoryController, TargetController, SkillController
    VFX/LightningRenderer.luau  # отрисовка молнии (Beam + зигзаг, затухание, очистка)
    VFX/DamageNumbers.luau   # плавающие цифры урона над целями
    ui/                      # WoW-стиль без внешних картинок, всё рисуется кодом:
                             #   Theme (палитра, качество предметов, шрифты), Chrome (золотые рамки, слоты, свечение),
                             #   RingBar, RadialCooldown, RingIcon, Glyphs, Window, Inventory, Shop, MicroMenu,
                             #   PlayerFrame, TargetFrame, Portrait (ViewportFrame), StatusBar, XpBar, CastBar,
                             #   Tooltip, Notice
```

В Studio проект попадает так:

| Папка            | Куда                                            |
| ---------------- | ----------------------------------------------- |
| `src/shared`     | `ReplicatedStorage.Shared`                      |
| `src/server`     | `ServerScriptService.Server`                    |
| `src/client`     | `StarterPlayer.StarterPlayerScripts.Client`     |

## Запуск

1. Установите [Rokit](https://github.com/rojo-rbx/rokit) и инструменты: `rokit install`.
2. Установите плагин Rojo в Studio (`rojo plugin install`) или с [Creator Store](https://create.roblox.com/store/asset/13916111004).
3. В корне репозитория: `rojo serve`, затем в Studio нажмите **Connect** в плагине Rojo.

Сборка файла места без Studio:

```
rojo build default.project.json -o build/gomoseko.rbxl
```

## Управление в игре

| Клавиша / действие        | Что делает                                                                   |
| ------------------------- | ---------------------------------------------------------------------------- |
| `1`-`4`                   | применить кольцо из слота (ЛКМ по слоту — то же самое)                       |
| `Q`                       | быстрый каст «Дуговой молнии» (пока кольцо надето)                           |
| ЛКМ по врагу              | выбрать цель (контур + фрейм цели); ЛКМ по пустому месту / `Esc` — снять     |
| `Tab` / `Shift+Tab`       | враги на экране в радиусе 100 studs: ближайший, далее по кругу / назад       |
| `I`                       | «Инвентарь»: ПКМ по кольцу — надеть/снять, или перетащить на слот панели     |
| ПКМ по слоту              | снять кольцо                                                                 |
| `B`                       | окно «Магазин» (строки-заглушки)                                             |
| `Esc`                     | закрыть открытые окна и снять цель                                           |

**Arc Lightning.** Молния бьёт цель (выбранную или, если цели нет, ближайшего врага в радиусе каста),
затем перескакивает на ближайших врагов в радиусе прыжка — по каждому не более раза за цепочку.
Бить можно только модели с тегом `Enemy` (CollectionService) и живым `Humanoid`; манекены в яме
получают тег при генерации карты. Урон, мана, кулдаун и дистанция проверяются на сервере
(`CombatService`), клиент только рисует молнию. Баланс — в `Configs/Skills/ArcLightningConfig.luau`;
чтобы услышать звук, впишите `SoundId` (`rbxassetid://...`) там же.

**Интерфейс.** Фреймы игрока и цели с круглыми портретами (ViewportFrame), полосы HP/маны/опыта, панель колец
с радиальным кулдауном и рамкой цвета качества, cast bar (время каста — `CastTime` в конфиге скилла, `0` = мгновенно),
плавающие цифры урона, повышение уровня за убийство врагов. Цвета и размеры — в `ui/Theme.luau` и `ui/Chrome.luau`.
Иконки рисуются кодом; чтобы подставить свою картинку кольца, задайте `Image = "rbxassetid://..."` в `RingsConfig`.

Состояние инвентаря, маны и опыта пока хранится в памяти сервера (без DataStore): `InventoryService.serialize/load` —
точка подключения сохранения. Манекены получают урон от касания `Tool`, респавн через 4 секунды.

## Важно при переходе с локального места

Если раньше хаб генерировался скриптом внутри Studio-места (например, `ServerScriptService.Script`),
**удалите старый скрипт** перед синхронизацией: иначе он при каждом запуске перезапишет карту.

## Палатки

Модель палатки грузится при старте сервера через `InsertService:LoadAsset` (ID в `Config.StallAssetId`):
берётся одна палатка из набора, уменьшается вдвое, из неё удаляются все скрипты и `Fire`, затем полосы
перекрашиваются в жёлтый, синий, красный и зелёный. Если загрузка не удалась, строятся процедурные палатки.
