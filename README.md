# gomoseko

A [Rojo](https://rojo.space) Roblox project: an underground hub (combat pit with training dummies, the "Portal Room"
temple, market stalls) with a World of Warcraft-style interface (player and target frames with HP/mana, 4 ring slots,
Inventory and Shop windows). The first ring is **Arc Lightning**.

The map is not stored in the repository as parts: it is **generated by code** when the server starts
(`src/server/BuildHub.server.luau`) into `Workspace.MainHub`. The whole project stays text-only and diff-friendly.

      OnboardingService.luau   # tutorial progress (profile), funnel analytics, reward

## Getting started

1. Install [Rokit](https://github.com/rojo-rbx/rokit) and the tools: `rokit install`.
2. Install the Rojo plugin in Studio (`rojo plugin install`) or from the [Creator Store](https://create.roblox.com/store/asset/13916111004).
3. In the repository root run `rojo serve`, then click **Connect** in the Rojo plugin in Studio.

Build a place file without Studio:

```
rojo build default.project.json -o build/gomoseko.rbxl
```

## Controls

| Key / action              | What it does                                                                  |
| ------------------------- | ----------------------------------------------------------------------------- |
| Attack button / `Q`       | cast the first ring skill on the selected target, or on the nearest enemy     |
| Small skill buttons / `E` / `R` | other ring skills (Fireball `E`, Meteor `R`); `1`-`4` cast by slot       |
| `1`-`4`                   | use the ring in that slot                                                     |
| Click on an enemy         | select it (outline) so the attack goes there; click empty space / `Esc` clears |
| `C` / `I`                 | Rings window: 4 slots on top, all rings below; tap a ring to wear / remove it |
| Tap a ring slot           | take the ring off (drag a ring onto a slot also works on PC)                  |
| `L`                       | DPS Leaderboard window (daily / weekly / all-time)                            |
| `O`                       | Settings: volume, Low graphics, summon effects (cinematic, shake, quick roll) |
| `G`                       | Ring Summon window (Gacha): summon ×1 / ×10, free roll, odds, auto roll       |
| `B`                       | Store window (Robux: Summon Crystals, luck potions, passes)                   |
| `T`                       | Rift window: enter or leave the wave arena (or use the cyan portal in the temple) |
| `V`                       | Boost window: your luck, AFK luck, Lucky Hour timer, link to luck potions      |
| `N`                       | Ring Index: collection book with rewards at 25 / 50 / 100 %                   |
| `Esc`                     | close open windows and clear the target                                       |

**Skills.** Every skill is a config in `Configs/Skills` with a `Kind` and a handler in `CombatService.HANDLERS`:
- **Arc Lightning** (`Chain`, Epic ring) — chain lightning that jumps between enemies.
- **Fireball** (`Projectile`, Ember Band, Rare 1 in 80) — a fireball flies to the target and explodes, hitting everything in
  `ExplosionRadius`.
- **Meteor** (`Meteor`, Starfall Ring, Legendary 1 in 7,500) — marks the ground, `Delay` seconds later a meteor hits the
  circle; an enemy that walks away in time is safe.
Damage, mana, cooldown, range and targets are validated on the server; `client/VFX/SkillEffects.luau` only draws the
effect. The first skill ring sits on the big Attack button, up to three more get small buttons around it. To add a
skill: a config, a registry entry on the server and client, a ring in `RingsConfig` and (for a new kind) a handler.

**Arc Lightning.** The lightning hits a target (the selected one or, with no target, the nearest enemy within cast
range), then jumps to the nearest enemies within the bounce radius, never hitting the same enemy twice in a chain.
Only models with the `Enemy` tag (CollectionService) and a living `Humanoid` can be hit; the dummies in the pit
get the tag when the map is generated. Damage, mana, cooldown and distance are validated on the server
(`CombatService`); the client only renders the lightning. Balance lives in `Configs/Skills/ArcLightningConfig.luau`;
to hear a sound, set `SoundId` (`rbxassetid://...`) there.

**Interface.** The look is a simple cartoon style (bright tiles, thick outlines, the rounded Fredoka One font): big coloured
emoji tiles on the left (Summon, Rings, Index, Shop, Boost, Ranks, Settings — a red dot marks a free roll or an Index
reward), big currency numbers bottom-left with the AFK luck line, the current tutorial step as large text at the top
and the Lucky Hour timer top-right. Palette: `Theme.Tiles`/`Theme.Gold*`, outlines and rounded panels: `ui/Chrome.luau`.
A compact player block (level, name, HP and mana bars), a thin XP bar at the bottom, one big **Attack**
button with a radial cooldown (no target needed — the server hits the nearest enemy; click an enemy to choose),
floating damage numbers and a level-up for killing enemies. Colours and sizes live in `ui/Theme.luau` and
`ui/Chrome.luau`. Icons are drawn in code; to use your own ring picture, set `Image = "rbxassetid://..."` in
`RingsConfig`. Fonts are built-in Roblox fonts (Fredoka One, GothamBlack for damage numbers) configured in
`shared/Fonts.luau`.

Inventory, mana and XP are currently kept in server memory (no DataStore): `InventoryService.serialize/load` is the
hook point for saving. Dummies take damage from `Tool` touches and respawn after 4 seconds.

## DPS arena and leaderboards

The training dummies in the pit **never die**: every hit counts towards a 30-second **DPS test** that starts with your
first hit (live DPS and a countdown at the top of the screen). The result is `total damage / 30`, calculated only on
the server (`DpsService`; the client just shows progress). Each finished test gives XP, gold and a few crystals, plus a
bonus for the first test of the (UTC) day. Best scores go to three `OrderedDataStore` boards shared by all servers —
**Daily**, **Weekly**, **All time** — shown on the board in the hub (it cycles every 8 seconds), in the Leaderboard
window (`L`) and refreshed every minute. When a week ends, the top 50 get Summon Crystals automatically on their next
login (`DpsConfig.WeeklyRewards`). Without DataStore access (Studio with API Services off) the boards show only the
current server. All numbers live in `Configs/DpsConfig.luau`; the pure math is checked by
`tools/tests/dps_math_test.luau`.

## Mobile, onboarding and analytics

- **Touch.** Tap the Attack button to cast (tap an enemy first to choose it), tap rings to wear them. The UI scales
  with the screen (`UIScale`, 0.6 to 1.4 by viewport height); on phones the menu is smaller, currency moves to the top
  right and the Attack button sits left of Roblox's jump button. Phones default to **Low graphics**
  (Settings, `O`): fewer lights and particles, no shadows or bloom. Check on real devices or the Studio emulator.
- **Onboarding.** `Configs/OnboardingConfig.luau` lists the first goals (equip ring, cast, summon); the tracker at the
  top of the screen shows the current one, finishing gives crystals. Progress is stored in the profile.
- **Analytics.** Onboarding steps go to the Roblox onboarding funnel; every currency source/sink is sent with
  `AnalyticsService:LogEconomyEvent` (Creator Hub → Analytics). Look at D1/D7 retention and where the funnel drops.

## Ring Summon (Gacha), economy and Robux

**Model.** RNG-game style (like Sol's RNG): the pool is `Configs/Rings/RingsConfig.luau`; every ring has a base rarity
`OneIn` ("1 in N", up to 1 in 50,000,000 for the Divine Genesis Ring). A roll goes through the rings from the rarest
to the most common; each hits with `min(1, luck / OneIn)`; the most common ring takes the remainder. The same math
(`shared/Gacha/GachaMath.luau`) produces the odds table shown to the player, so the displayed chances are the real
ones and add up to exactly 100%. There is no pity system (not used in this genre). **Luck** = 1 + (ring luck + paid
luck) / 100, capped by `GachaConfig.Luck.Max`. Duplicates become Ring Essence. Epic or better finds can be announced
to everyone (`GachaConfig.Announce.MinOneIn`).

**Currencies.** Gold and Summon Crystals come from kills and level-ups (numbers in `GachaConfig.Rewards`), Ring
Essence from duplicates; a free roll is available every 20 hours. Rings give passive bonuses (damage, mana,
cooldown, range, luck) that are applied on the server and listed in the Rings window.

**Saving.** `DataService` keeps the player profile in a DataStore. In Studio enable *Game Settings → Security →
Enable Studio Access to API Services*; otherwise data lives only in memory and real purchases are not confirmed.

**Robux.** Fill in the IDs in `Configs/MonetizationConfig.luau` after creating the Developer Products (crystal packs,
luck potions) and Game Passes (Auto Roll, Fast Roll, Lucky Charm) in the Creator Hub. Until an ID is set, the Store
shows "Not set up"; in Studio the "Test Grant" button gives items without Robux. `MonetizationService` owns the single
`ProcessReceipt`: purchases are idempotent by `PurchaseId` and are confirmed only after the profile is saved.

**Roblox "Paid Random Items" policy.** Random rewards bought with Robux (or with Robux-bought currency) must show all
outcomes with numeric odds in percent (summing to 100%) *before* purchase, explain paid luck boosts numerically, and be
disabled where `PolicyService` reports `ArePaidRandomItemsRestricted`. The Summon window's "Odds / Details" and the
Store's "View odds" cover the first two; for restricted players paid summons, paid luck and the paid Store items are
turned off and only the free roll remains. Review the current
[policy](https://create.roblox.com/docs/en-us/production/monetization/paid-random-items) before enabling real sales.

## Roll "juice", cinematic rare finds and text size

- **Cinematic rare roll** (`client/VFX/RareCutscene.luau`): a find of `GachaConfig.Cinematic.MinOneIn` (1 in 1,000) or
  rarer hides the HUD for 2–3 s, blocks the controls (`PlayerModule:GetControls():Disable()`), tweens the camera onto
  your character (TweenService), shakes the screen lightly, dims the world with a `ColorCorrectionEffect`, then a
  thunder boom and a flash in the ring's quality colour. Space / tap / gamepad A skips it; death or any error restores
  camera and controls. The result is decided by the server before this starts — it is only a presentation.
- **Reveal style by tier** (`ui/Summon.luau`): the charging orb takes the colour of the best find (Epic+), sparks and a
  shockwave scale with rarity, "1 in N" counts up, card flips play a tick whose pitch rises, the multi-roll shows
  "Best find". Settings → *Summon effects*: Cinematic rolls, Screen shake, Quick roll (no animation) and Controller
  vibration (gamepads only — Roblox has no API for phone vibration).
- **Text size**: sizes are bigger (`Theme.TextSize`) and the UI scale is `clamp(height / 800, 0.6, 1.4)` so text stays
  readable on 1080p+ monitors; on phones please test on a real device.

## Overhead title, AFK luck and Lucky Hour

- **Overhead title** (`server/Services/OverheadTitleService.luau`): a `BillboardGui` over the head shows the nickname,
  your rarest equipped ring and `[1 in X]`; it is rebuilt on every equip/unequip. Rings at `Overhead.MinGradientOneIn`
  (1 in 500) or rarer get a `UIGradient` wave of colour, `RainbowOneIn` (1 in 1,000,000)+ a rainbow;
  `client/VFX/TitleGradient.luau` animates them (one shared loop, culled beyond 70 studs).
- **AFK Playtime Luck** (`PlaytimeLuckService`): every 10 minutes on the same server adds +0.1x luck, up to +1.0x;
  kept in server memory only, so leaving resets it. The server sends the value over `PlaytimeLuck` /
  `LuckBoostsGet`; the HUD line "AFK Luck: +0.2x" shows it. Config: `GachaConfig.Playtime`.
- **Lucky Hour** (`LuckEventService`): every 30 minutes for 5 minutes everyone gets +1.0x luck (schedule from the unix
  clock, so all servers agree). Config: `GachaConfig.LuckEvent`. Both bonuses are free luck sources: they apply to the
  free roll too and appear in the luck breakdown and the odds table, so the shown odds stay the real ones.

## Rift (endless waves)

The main activity that earns Summon Crystals: enter the **Rift** (cyan portal in the temple, the Rift tile or `T`) and fight
waves of enemies in a separate arena (`server/Hub/RiftArena.luau`). One shared run per server: the first player starts it
(10 s lobby), others can join between and during waves; enemies get tougher with the wave and with the number of players.
Types: Grunt, Runner (from wave 3), Brute (from wave 6) and a Titan boss every 10th wave (`Configs/RiftConfig.luau`,
`shared/Rift/WaveMath.luau`, tested). Each cleared wave pays Crystals and Essence by your share of the damage, kills pay
extra, and your best wave is saved (`profile.Rift.BestWave`). If you fall you keep what you earned. A wave that drags on
for 150 s enrages the enemies. You need a ring with a skill equipped to enter (the admin menu can bypass that).
Enemies are plain Humanoid models with a shared AI loop (`RiftEnemyAI`, straight-line movement, melee hits), tagged
`Enemy` so every skill works on them. Admin menu: *Rift: wave 1/10/30*, *Kill Rift enemies*, *Leave Rift*.
Balance numbers (HP, damage, rewards, timings) are all in `RiftConfig`; they are untested in play and need tuning.

## Admin menu (testing)

`F2` or the **Admin** tile in the left menu opens a window with: give any ring / all rings / reset rings; add Crystals,
Gold, Essence; set level; **Infinite mana**, **No cooldown**, refill mana, reset cooldowns; spawn mortal test enemies
(`Dummy` stands still, `Mover` wanders — good for Fireball and Meteor) and clear them; start Lucky Hour or add AFK-luck
time. Access is decided on the server for every action (`AdminService`, `shared/AdminAccess.luau`): in Studio always,
on a live server for the place owner (if the place belongs to a user) and for UserIds listed in
`Configs/AdminConfig.luau` (`UserIds = { 123456789 }`). Non-admins never get the window, and their attempts are logged with
`warn`. Set `Enabled = false` there to switch the menu off entirely before a release. Limits: 10 enemies at once, 40 total,
currency steps up to 1e9, level 1–100.

## Ring Index

`N` opens the Index: every ring in `RingsConfig` in order of rarity; found rings show their icon, name and
`1 in N`, missing ones a dark silhouette with `???` (their rarity stays visible — nothing is hidden about the odds).
Rewards at 25 / 50 / 100 % of the collection (`GachaConfig.Index.Milestones`) are claimed once, validated on the server
(`IndexService`, claims stored in `profile.Index.Claimed`). "Found" is derived from the player's rings, so existing
players get their Index automatically. Progress math is in `shared/Gacha/IndexMath.luau` (tested).

## Sounds

The sounds (`arc_lightning_charge.ogg` — cast charge, `arc_lightning_zap.ogg` — impact crackle,
`thunder_boom.ogg` — rare-roll thunder, `reveal_tick.ogg` — card flip tick, `fireball_cast.ogg` — Fireball/Meteor cast,
`explosion.ogg` — explosion, all in `assets/audio`) are synthesized by `tools/make_audio.py` (re-run it to regenerate). Roblox can only play uploaded
assets, so upload them once:

1. `rokit add jacktabscode/asphalt` (adds [Asphalt](https://github.com/jackTabsCode/asphalt) to `rokit.toml`).
2. Put your Roblox UserId into `asphalt.toml` (`[creator] id`).
3. Create an Open Cloud API key with `asset:read` and `asset:write` permissions
   ([Creator Dashboard](https://create.roblox.com/dashboard/credentials)) and run
   `ASPHALT_API_KEY=<key> asphalt sync` (PowerShell: `$env:ASPHALT_API_KEY = "<key>"; asphalt sync`).
   Never commit or share the key.
4. Asphalt rewrites `src/shared/Assets.luau` and creates `asphalt.lock.toml` — commit both.

Alternative without Asphalt: import the files in Studio (Asset Manager → Bulk Import) and paste the
`rbxassetid://...` values into `Sounds.Manual` in `src/shared/Sounds.luau`. Until IDs exist the game stays silent.
Volume is `Config.Audio.SfxVolume` and `SoundVolume` in `ArcLightningConfig`.

## Lighting and atmosphere

All lighting numbers are in `Config.Lighting` (`src/shared/Config.luau`): ambient colours, fog, atmosphere, bloom,
colour correction, the moonlight shaft through the ceiling opening, and the torch colour/brightness. Warm light comes
only from braziers, lanterns and stalls; the cave itself is lit with cool blue light. Torch and lantern lights carry the
`Torch` tag and flicker on the client (`VFX/TorchFlicker.luau`).

## Switching from a local place

If the hub used to be generated by a script inside a Studio place (for example `ServerScriptService.Script`),
**delete the old script** before syncing: otherwise it overwrites the map on every run.

## Stalls

The stall model is loaded when the server starts via `InsertService:LoadAsset` (ID in `Config.StallAssetId`):
one tent is taken from the set, halved in size, stripped of scripts and `Fire`, and its stripes are recoloured to
yellow, blue, red and green. If loading fails, procedural stalls are built instead.
